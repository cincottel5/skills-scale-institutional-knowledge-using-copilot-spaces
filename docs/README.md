# OctoAcme Project Management Docs

Welcome to the OctoAcme Project Management documentation hub. This folder contains the living process documents that guide how OctoAcme plans, executes, and continuously improves its project delivery.

## About OctoAcme's Project Management Approach

OctoAcme uses an **iterative, customer-first delivery model** built on five core principles:

| Principle | Description |
|-----------|-------------|
| **Customer-first** | Every decision prioritizes customer value and usability. |
| **Iterative delivery** | Work is broken into small, testable increments shipped frequently. |
| **Clear ownership** | Each project has a named **Project Manager (PM)** and **Product Lead (PdM)** accountable for delivery and outcomes. |
| **Data-informed decisions** | Impact is measured and teams iterate based on evidence, not assumptions. |
| **Psychological safety** | Feedback and learning are actively encouraged at every stage. |

Projects follow a five-phase lifecycle: **Initiation → Planning → Execution → Release → Retrospective**. All process documents below are "living" — they are expected to evolve as the team learns.

## How to Use These Docs

1. **New team members** — Start with the [Project Management Overview](octoacme-project-management-overview.md) to understand OctoAcme's approach, then read the document relevant to the phase your project is currently in.
2. **Project Managers & PdMs** — Use the initiation, planning, and release docs as checklists and templates for your project artifacts.
3. **Developers & QA** — The execution-and-tracking and roles-and-personas docs clarify day-to-day workflows and expectations.
4. **All contributors** — These documents are living references. If something is unclear or out of date, propose an update (see below).

> **Tip:** If you want Copilot Spaces to use these docs as context, add or symlink the relevant files into your project's `.copilot/` folder.

## Contributing and Proposing Updates

These process documents are maintained collaboratively. To suggest a change or addition:

1. Open a new issue using the [**Add/Update Content to Process Docs** issue template](../.github/ISSUE_TEMPLATE/add-update-content-to-process-docs.yml).
2. Describe the document(s) affected, the proposed change, and the rationale.
3. The PM or PdM for the relevant process area will review and coordinate updates.
4. Once approved, submit a pull request targeting the `docs/` folder with your changes.

All contributions should align with OctoAcme's core principles and be written to provide clear, actionable guidance.
